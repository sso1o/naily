# 글쓰기 화면 재구성 보고서

## 확인한 현재 구조와 기능

작업 시작 시 실제 `router` 호출, 작성 화면, BlogEditor, EditorToolbar, PostBlockRenderer, 이미지 꾸미기와 useUnsavedChanges를 확인했다. Expo 57.0.19 / React Native 0.86.3 / expo-image-picker 57.0.15 / safe-area-context 5.7.0을 사용한다. 패키지와 폰트는 추가·변경하지 않았다.

| 기능 | 기존 구현 | 이번 처리 |
|---|---|---|
| 새 글 | public/shop/magazine mode, 예시 제목 블록·본문 초깃값 | 빈 본문 하나로 시작, 저장 스키마 유지 |
| 수정 | editId로 allPosts 조회, 이미지 장식 깊은 복사 | 같은 방식 유지, 기존 샵 전용 상태도 유지 |
| 제목/본문 | 단일 제목 입력과 블록별 입력 | 문서형 자동 높이 입력, 제목 다음/Enter로 본문 포커스 |
| 등록 검증 | 제목 trim 후 필수 검사, 본문 필수 조건 없음 | 동일, 빈 제목이면 등록 비활성화 |
| 등록 | 로컬 배열 갱신, 성공 Alert 뒤 상세 이동 | ref 잠금·진행 표시 추가; 네이티브 성공 Alert 유지, 웹은 상세로 바로 이동 |
| 미리보기 | 작성 화면 안 preview 분기 | 상단 글 메뉴 → 별도 전체 화면 Modal, PostBlockRenderer 재사용 |
| 카테고리 | 일반 5개·샵 7개·매거진 3개 가로 칩 | 작은 현재 카테고리 한 줄 → 선택 시트 |
| 태그 | 항상 노출된 입력, 공백 분리 및 선행 # 하나 제거 | 하단 태그 추가 → 입력 시트, 기존 규칙 유지, 입력한 태그 칩·삭제 |
| 사진 | 권한 요청 후 이미지 한 장씩 추가/변경 | 하단 사진 도구, 비동기 최신 문서 반영·중복 선택 방지 |
| 사진 삭제·순서 | 모든 블록 헤더의 위/아래/삭제 | 사진 선택 시 액션, 순서·삭제 메뉴; 문단/구분선도 더보기에서 유지 |
| 이미지 꾸미기 | decoratedImage와 draftKey로 별도 라우트 왕복 | 동일 경로; 반환 결과 한 번 반영해 사진 변경 뒤 오래된 결과가 덮어쓰지 않게 처리 |
| 텍스트 서식 | 제목/본문 추가, 굵기·크기·왼쪽/가운데, 구분선 | 하단 서식/더보기 시트로 이동, 저장 값·기존 크기 순환 유지 |
| 공개·댓글·알림 옵션 | 없음 | 새로 추가하지 않음 |
| 샵 권한/노출 | 진입 화면의 역할 분기 및 isShopOnly | 기존 진입 조건 유지; 작성 화면에는 현재 계정/샵 전용 한 줄, 일반 모드에는 숨김 |
| 매거진 | mode=magazine, 첫 사진을 홈 데이터에 연결 | 유지; 편집 시 연결 항목 갱신으로 중복 방지. 홈 카드가 연결한 일반 글을 매거진 글로 자동 분류하지 않음 |
| 이미지/태그 개수 제한 | 없음 | 임의 제한 없음; 원래의 단일 사진 선택 흐름 유지 |
| 태그 중복/특수문자 | 중복 허용, 별도 특수문자 검증 없음 | 기존 저장 규칙 그대로 유지 |
| 작성 취소 | title/category/tagText/blocks 스냅샷 + usePreventRemove | 유지; 빈 새 글 즉시 종료, 변경 시 확인; 이미지 화면 push는 취소가 아님 |
| 임시저장 | 이미지 꾸미기 왕복용 메모리 map만 존재 | 자동 임시저장 추가 없음; 브라우저 새로고침/앱 재시작 시 보존 보장 없음 |
| 키보드 | ScrollView의 keyboardShouldPersistTaps만 존재 | KeyboardAvoidingView + 자동 높이 입력 + 하단 도구 + 시트 키보드 대응 |
| Alert | 제목 검증, 사진 권한·실패, 저장 성공, 작성 취소 | 유지; 저장 실패 안내 추가 |

## 변경 전과 후

**이전:** 헤더(미리보기) → 제목 → 카테고리 칩 묶음 → 태그 입력 섹션 → 본문 블록 제목 → 큰 텍스트 도구들 → 사용법 → 테두리 카드마다 블록 종류/순서/삭제/입력/서식 상태 → 맨 아래 등록.

**현재:** 상단 취소·새 글/글 수정·글 메뉴·등록 → 작은 게시판 선택 → 제목 → 바로 본문·이미지·구분선 → 입력한 태그 → 화면/키보드 위 사진·서식·태그·더보기 도구.

카드 테두리와 둥근 배경, HEADING/TEXT 블록 라벨, 상시 순서 버튼, 본문 블록 섹션 제목, 상시 도움말·서식 상태와 하단의 별도 등록 버튼을 제거했다. 기능 자체는 선택 메뉴에 남겼다. 원래 실제 Switch 토글은 없었으며, 새 Switch를 만들지 않았다.

| 직접 노출하던 항목 | 현재 위치 |
|---|---|
| 카테고리 전체 칩 | 게시판 선택 시트 |
| 큰 태그 입력 | 태그 시트, 본문 아래에는 입력한 태그만 |
| 굵기·크기·정렬 및 서식 상태 | 선택한 문단의 서식 시트 |
| 소제목·문단·구분선 추가, 블록 이동·삭제 | 더보기 시트 |
| 사진 변경·꾸미기·순서·삭제 | 사진을 선택했을 때만 표시 |
| 미리보기 모드 전환 | 상단 글 메뉴 → 전체 화면 미리보기 |

## 입력·이미지·미리보기 보호

- 편집 입력창은 안정적인 블록 id로 유지하며 selection을 강제로 덮어쓰지 않는다. 미리보기 Modal 뒤의 편집기는 마운트 상태를 유지한다.
- 공통 WritingTextInput은 iOS/Android에서 contentSize로 높이를 맞추고, 웹에서는 textarea의 auto 높이를 측정하여 긴 입력 후 삭제해도 다시 줄어들게 한다. 제목·본문 각각의 중첩 세로 스크롤을 없앴다.
- 웹의 설치된 react-native-web은 submitBehavior만으로 multiline Enter 제출을 처리하지 않아 웹에 한해 기존 blurOnSubmit 호환 옵션을 함께 사용한다. 라이브러리의 한글 조합 검사 흐름을 그대로 따른다.
- 사진 권한/선택 호출은 ref 잠금으로 중복 실행을 막는다. 결과는 setBlocks의 함수형 갱신으로 반영한다. 선택 취소·화면 이탈 후 반환은 문서를 바꾸지 않는다.
- 사진 삭제 후 마지막 블록까지 없어지면 빈 본문을 제공해 바로 다시 쓸 수 있다. 이미지가 없는 빈 첨부 박스는 없다.
- 저장은 실제 기존 로컬 배열을 갱신한다. 저장 중 버튼/입력을 비활성화하고 잠금은 상세 이동까지 유지한다. 오류 시 작성 내용은 유지하고 재시도할 수 있다.
- PostBlock/CommunityPost 타입과 사용자 콘텐츠 크기·굵기·정렬·장식 저장 형식은 변경하지 않았다. 사진·태그·본문을 저장하는 서버나 자동 임시저장처럼 보이게 만들지 않았다.

## 키보드·SafeArea·탭

작성 라우트는 탭 내부가 아니라 루트 Stack 위에 있어 하단 앱 탭이 원래 노출되지 않는다. 탭 네비게이션은 수정하지 않았다.

상하 SafeArea 안에 KeyboardAvoidingView( iOS padding / Android height )와 문서 ScrollView, 문서 밖 하단 도구를 배치했다. 문서 하단 여백을 두어 마지막 줄과 도구가 겹치지 않게 했다. 네이티브에서 문단 끝 입력 시 실제 도구 높이를 반영해 입력창을 키보드 위로 스크롤하며, 문단 중간을 고칠 때는 강제로 끝으로 이동시키지 않는다. 시트에도 키보드 회피와 스크롤·하단 SafeArea가 있다.

iOS는 시트가 닫힌 뒤 미리보기 Modal을 열고, 문단 추가 시 시트 dismiss 이후 포커스를 주도록 처리했다. 미리보기의 Android 뒤로가기는 편집으로 복귀한다. 작성 라우트 종료는 기존 usePreventRemove가 보호한다.

## 실기기 추가 확인

iOS/Android 실행 환경이 없어 아래는 구현/코드 및 모킹 테스트까지만 확인했다.

- 실제 한글 IME 조합 중 커서 안정성, 긴 문단의 중간/끝 입력과 키보드 자동 스크롤.
- 작은 기기와 큰 시스템 글자에서 도구 높이, 앱 바, SafeArea, 키보드 닫기/열기 및 태그 시트.
- iOS 시트 dismiss → 미리보기/본문 포커스, 사진 권한 제한 상태, 사진 선택 후 복귀.
- Android 하드웨어 뒤로가기: 시트/미리보기 닫기와 작성 취소 확인; 시스템 resize 모드에 따른 키보드 여백.
- iOS 스와이프 뒤로가기 취소/폐기, 저장 중 네이티브 Alert 확인 후 한 번만 상세 이동.
- 미리보기 복귀 시 네이티브 selection/스크롤 복원 정도. 입력기는 유지하지만 OS별 키보드 재표시까지 자동 보장하지 않는다.
