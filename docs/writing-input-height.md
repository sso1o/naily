# 글쓰기 입력 높이 수정 결과

## 원인

현재 코드를 확인한 결과, 본문 자체에 단일 블록 `minHeight: 220`, 모든 문단의 기본 `minHeight: 44`가 있었다. 이를 감싼 blocks에는 `minHeight: 260`과 `flexGrow: 1`, 문서 contentContainer에도 `flexGrow: 1`이 있어 내용이 없어도 남은 높이를 채우고 태그를 아래로 밀었다.

제목은 최소60/세로패딩14, 태그는 최소88/최대180/세로패딩12였다. 태그는 자동 높이 컴포넌트가 아닌 일반 multiline 입력이어서 내부 스크롤이 가능했다. 공통 자동 높이는 네이티브 contentSize와 웹 scrollHeight에 무조건2를 더했다. 입력별 state는 원래 분리되어 있었으며, 공유 state가 원인은 아니었다.

기존 글 웹 검증에서는 높이를 0으로 측정하는 동안 문서 스크롤바가 사라져 입력 폭이 잠깐 넓어지고, 줄 수가 적게 측정되는 문제도 발견했다. 표시 중인 실제 폭을 잠시 고정한 상태에서 높이를 측정하고 원래 폭으로 복원하도록 수정했다. 기존 4줄 본문이 72로 측정되던 문제를 96으로 바로잡았다.

## 최소 높이 (기본 글자 배율)

| 영역 | 이전 설정 | 현재 계산 및 높이 |
|---|---|---|
| 글 제목 | 최소60, 상하14 패딩 | titleMedium 줄높이28 + 상하6씩 + 구분선1 = **41** |
| 일반 본문 | 최소44, 단일 블록220; 부모 최소260 및 잔여공간 확장 | bodyMedium 줄높이22 × 3, 패딩0 = **66** |
| 소제목 블록 | 최소44, 단일 블록일 때220 | 사용자 서식 줄높이 × 1 (기본 토큰28, 기존 생성 서식20/30은30) |
| 태그 입력 | 최소88, 최대180, 상하12씩 | bodyMedium 줄높이22 + 상하6씩 = **34** |
| 구분선 블록 | 최소44 | 상하8씩 + 얇은 구분선, 선택 기능 유지 |

이미지는 기존 비율을 유지한다. 사용자가 선택한 본문 서식이 있으면 해당 줄높이로 3줄을 계산한다. 따라서 기존 16/24 본문의 최소 높이는72다. 큰 시스템 글자 배율은 최소 줄 높이 계산에 반영하며 폰트 크기를 줄이지 않는다.

## 자동 높이 처리

각 WritingTextInput이 자신의 최소 줄 수, 현재 콘텐츠 높이, 스타일 패딩·테두리 값을 관리한다. 네이티브는 `max(최소 높이, contentSize.height)`를 사용하며 측정값을 정수로 정리하고 같은 값/1px 이하 오차는 갱신하지 않는다. 빈 값으로 돌아오면 최소 높이로 표시하고 이전 측정을 초기화한다.

설치된 RN 소스에서 iOS RCTUITextView.contentSize는 textContainerInset(패딩)을 포함하고 Android ReactTextContentSizeWatcher도 텍스트 레이아웃 높이에 compoundPadding을 합산함을 확인했다. 따라서 네이티브 측정값에 패딩이나 임의의2를 다시 더하지 않는다. textAlignVertical=top, includeFontPadding=false, scrollEnabled=false를 적용한다.

웹은 실제 입력 폭 유지 → min-height/height를0으로 초기화 → scrollHeight 측정 → 최소 높이와 비교 → 테두리만 보정 → 계산한 높이 적용 → 폭 복원 순서다. 초기 및 실제 레이아웃/값/폭/서식 변경 시 측정하며 resize 핸들과 내부 세로 스크롤을 비활성화한다. 측정은 네이티브 높이 state를 갱신하지 않는다.

blocks와 문서의 flexGrow, blocks 최소260, 단일 본문 최소220을 제거했다. 화면 전체 컨테이너의 flex:1, 고정 하단 도구, SafeArea와 키보드 회피는 유지한다. 태그 시트 ScrollView는 flexGrow:0/flexShrink:1로 내용만큼만 열리고 maxHeight80%를 넘으면 시트 안에서 스크롤된다. 태그가 있을 때만 입력 아래 칩을 표시한다. 메인 태그 추가와 기존 칩 삭제 방식은 유지한다.

## 수정 파일

- `app/write.tsx`: 제목 패딩·최소 높이, 태그 자동 높이 입력과 조건부 칩.
- `components/BlogEditor.tsx`: 본문/소제목별 최소 줄 수, 강제 확장 제거, 구분선 여백.
- `components/WritingTextInput.tsx`: 독립 최소/콘텐츠 높이 계산, 웹 폭 보존 측정, 축소 및 오차 처리.
- `components/WritingSheet.tsx`: 내용 기반 시트 ScrollView 크기.
- `tests/writing-height.test.cjs`: 높이 회귀 테스트4개.
- `docs/writing-input-height.md`: 이 보고서.

EditorToolbar는 확인했지만 변경하지 않았다. 저장·데이터 타입·취소 보호·이미지·미리보기·역할 분기·기존 타이포그래피 토큰과 패키지는 변경하지 않았다.

웹 검증은 데스크톱 브라우저의 모바일 크기 뷰포트에서 수행했다. 모바일 소프트 키보드가 열린 상태나 실제 한글 IME는 검증하지 못했다.

- `npm run typecheck`: 통과.
- `node --test tests/*.test.cjs`: **33/33 통과** (기존29 + 높이 테스트4).
- 높이 테스트: 입력별 측정 분리, 축소·최소 높이,1px 흔들림, 글자 확대, 웹 스크롤바 폭 변화 회귀.
- 린트 설정/스크립트가 없어 린트 미실행.

실기기에서는 iOS/Android의 초기 onContentSizeChange, 긴 내용 삭제, 여러 빈 블록, 큰 글자 배율, 한글 조합 중 커서, 키보드가 열린 태그 시트·문서 마지막 줄을 확인해야 한다. 기존 키보드 회피와 SafeArea를 유지했지만 네이티브 사용감까지 확인했다고 주장하지 않는다.
